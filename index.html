📖 Understanding Scheduling Metrics
CT
Completion Time — The time at which a process finishes execution.
TAT
Turnaround Time — Total time from arrival to completion. TAT = CT − AT
WT
Waiting Time — Time spent waiting in the ready queue. WT = TAT − BT
RT
Response Time — Time from arrival until the process first gets CPU. RT = First CPU Time − AT
%
CPU Utilization — Percentage of time the CPU is busy. = (Total Time − Idle Time) / Total Time × 100
λ
Throughput — Number of processes completed per unit time. = Number of Processes / Total Time

📚 Learn CPU Scheduling

Understanding how each scheduling algorithm works

🎓 What is CPU Scheduling?

CPU Scheduling is the process by which the Operating System decides which process in the ready queue gets to use the CPU at any given time. It is a fundamental concept in Operating Systems that directly affects system performance and responsiveness.


The scheduler selects processes from the ready queue and allocates the CPU to them. The goal is to maximize CPU utilization, throughput, and fairness while minimizing waiting time, turnaround time, and response time.


🔹 Preemptive: CPU can be taken away from a running process
🔹 Non-Preemptive: Once started, a process runs to completion
🔹 Starvation: A process waits indefinitely for CPU
🔹 Convoy Effect: Short processes wait behind long ones
FCFS

First Come First Serve

Non-Preemptive

How it works: Processes are executed in the order they arrive in the ready queue, similar to a queue at a ticket counter. The first process to arrive is the first to get the CPU.

Real-world analogy: Like waiting in a line at a bank — first person in line gets served first, regardless of how long their transaction takes.

✅ Advantages
  • Simplest to implement and understand
  • Fair — no starvation possible
  • No overhead of context switching decisions
  • Predictable execution order
❌ Disadvantages
  • Convoy effect: short processes wait behind long ones
  • High average waiting time
  • Not suitable for time-sharing systems
  • Non-preemptive — no priority handling
📌 Used in: Batch processing systems, print queues
⏱️ Time Complexity: O(n log n) for sorting
SJF

Shortest Job First

Non-Preemptive

How it works: When the CPU is free, the process with the shortest burst time among all arrived processes is selected. Ties are broken by arrival time.

Real-world analogy: Like an express checkout lane — customers with fewer items (shorter jobs) go first.

✅ Advantages
  • Optimal average waiting time (for non-preemptive)
  • Good for batch systems where burst times are known
  • Minimizes average turnaround time
❌ Disadvantages
  • Starvation: long processes may wait indefinitely
  • Burst time must be known in advance
  • Not practical for interactive systems
  • Difficult to predict CPU burst length
📌 Used in: Batch operating systems, process scheduling
⏱️ Produces minimum average WT for a given set of processes
PRI

Priority Scheduling

Non-Preemptive & Preemptive

How it works: Each process is assigned a priority. The CPU is allocated to the process with the highest priority (lowest priority number in this implementation). In preemptive mode, a running process is interrupted if a higher-priority process arrives.

Priority convention: In this application, a lower priority number means higher priority (e.g., Priority 1 is more important than Priority 3).

Real-world analogy: Like an emergency room — patients are treated based on severity (priority), not arrival order.

✅ Advantages
  • Important processes get CPU first
  • Flexible — priorities can reflect urgency
  • Suitable for real-time systems
  • Can be combined with other algorithms
❌ Disadvantages
  • Starvation: low-priority processes may never execute
  • Priority inversion problem
  • Determining priorities can be complex
  • Solution: Aging (increasing priority over time)
📌 Used in: Windows, Linux, RTOS
⏱️ Preemptive version used in most modern OS
RR

Round Robin

Preemptive (Time-Sliced)

How it works: Each process gets a fixed time slice (quantum). If the process doesn't finish within its quantum, it is preempted and placed at the back of the ready queue. The next process in the queue then gets the CPU.

Time Quantum: The performance of Round Robin depends heavily on the quantum size. A very small quantum causes too many context switches; a very large quantum degrades to FCFS.

Real-world analogy: Like a group presentation where each person gets exactly 2 minutes to speak, then the next person goes.

✅ Advantages
  • Fair — every process gets equal CPU time
  • No starvation
  • Good for time-sharing systems
  • Low response time for short processes
❌ Disadvantages
  • Performance depends on quantum size
  • Context switching overhead
  • Higher average WT than SJF
  • No priority consideration
📌 Used in: Unix, Linux, Windows time-sharing
⏱️ Typical quantum: 10-100 milliseconds
SRTF

Shortest Remaining Time First

Preemptive (SJF Variant)

How it works: The preemptive version of SJF. At each time unit, the process with the shortest remaining burst time is selected. If a new process arrives with a shorter remaining time than the currently running process, the current process is preempted.

Real-world analogy: Like a hospital where a patient with a quick procedure can bump someone who still needs a long treatment.

✅ Advantages
  • Optimal average waiting time among all algorithms
  • Better response time for short processes
  • More efficient than non-preemptive SJF
❌ Disadvantages
  • Starvation of longer processes
  • High overhead of frequent preemptions
  • Requires knowing remaining burst time
  • Complex to implement
📌 Used in: Advanced scheduling in RTOS
⏱️ Also known as: Preemptive SJF or SRTF

ℹ️ About This Project

CPU Scheduling Visualizer & Performance Analyzer

📄 Project Abstract

This project is an interactive web-based application that demonstrates and compares various CPU scheduling algorithms used in Operating Systems. It allows users to input process data, visualize execution through Gantt charts, analyze performance metrics, and compare algorithms side by side. The tool serves as an educational aid for understanding how an operating system's CPU scheduler works and how different algorithms impact system performance.

🎯

Objectives

Implement, visualize, and compare CPU scheduling algorithms. Provide an interactive learning tool for OS concepts with accurate calculations and clear visualizations.

🛠️

Technology Stack

HTML5 CSS3 JavaScript ES6 No Frameworks
📊

Algorithms

FCFS, SJF (Non-Preemptive), Priority (Non-Preemptive & Preemptive), Round Robin, and SRTF (Preemptive SJF).

✅

Features

Interactive process input, dynamic Gantt charts, detailed metrics, algorithm comparison with bar charts, dark/light mode, and educational content.

💻

System Requirements

Any modern web browser (Chrome, Firefox, Edge, Safari). No server or installation required — runs entirely in the browser.

📘

Course

Operating Systems — College Level Capstone Project. Covers process scheduling, CPU management, and performance analysis.

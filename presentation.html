Background & Motivation

The CPU Scheduling Challenge

Bridging the gap between theoretical OS concepts and dynamic real-world execution.

⚠️ Core Problem Statement

In multi-programmed systems, multiple processes reside in the ready queue competing for the central processor. Choosing which process to dispatch is critical for responsiveness and throughput.

  • Static Textbook Illustrations: Textbooks present static, fixed-time Gantt charts that fail to convey dynamic preemption behavior.
  • Complex Preemption Boundaries: Visualizing how an incoming process preempts an active process in SRTF or Preemptive Priority is difficult without interactive tools.
  • Round Robin Timing Ties: Understanding queue re-ordering when time quantum expiration coincides with new arrivals.
🎯 Project Objectives & Solution

We designed an end-to-end interactive simulation platform that models the CPU scheduling engine with 100% mathematical fidelity.

  • Multi-Algorithm Coverage: Real-time simulation of 6 essential scheduling policies (FCFS, SJF, Priority NP/P, Round Robin, SRTF).
  • Dynamic Interactive Gantt Chart: Proportional scaling, explicit idle intervals, and step-by-step playback.
  • Quantitative Comparison: Side-by-side benchmarking of Waiting Time, Turnaround Time, Response Time, CPU Utilization, and Throughput.
  • Zero Dependencies: Built completely with pure HTML5, CSS3, and ES6 JavaScript.

Algorithms Overview

6 Scheduling Algorithms Implemented

Covering non-preemptive, priority-driven, time-sliced, and optimal preemptive paradigms.

1. FCFS

Non-Preemptive

Dispatches processes strictly in order of arrival time ($AT$).

Trade-off: Simple and fair in arrival sequence, but suffers from the Convoy Effect when long bursts precede short jobs.

2. SJF (Non-Preemptive)

Non-Preemptive

Selects ready process with smallest Burst Time ($BT$).

Trade-off: Provably minimizes average waiting time among non-preemptive algorithms. Susceptible to long-job starvation.

3. Priority (NP & P)

Both Modes Supported

Lower integer = Higher priority ($1 > 2 > 3$).

Trade-off: Guarantees high-urgency tasks run first. Preemptive mode interrupts immediately upon arrival of higher priority.

4. Round Robin (RR)

Preemptive (Time-Sliced)

FIFO ready queue with configurable time quantum ($q$).

Trade-off: Excellent response time and interactive fairness. Sensitive to quantum size (context switch overhead).

5. SRTF (Preemptive SJF)

Preemptive

Selects process with shortest remaining burst time.

Trade-off: Yields theoretical minimum average waiting time across all algorithms. Requires frequent preemption evaluations.

6. CPU Idle Handling

Seamless Gap Detection

When ready queue is empty, advances clock directly to next arrival.

Trade-off: Explicitly logs idle periods in Gantt chart, maintaining timeline continuity and true CPU utilization %.

Mathematical Framework

Performance Metrics & Invariants

Rigorous mathematical formulations validated against textbook axioms.

📐 Metric Formulations
Turnaround Time (TAT) = CT - AT
Waiting Time (WT) = TAT - BT
Response Time (RT) = First CPU Start - AT
CPU Utilization (U) = ((Total - Idle) / Total) × 100%
Throughput (Th) = Completed Processes / Total Time
🛡️ Mathematical Invariants Verified

Every algorithm run is automatically validated against these fundamental rules:

  • Non-Preemptive Equality: In all non-preemptive algorithms (FCFS, SJF, Priority-NP), Response Time strictly equals Waiting Time: $RT = WT$.
  • Preemptive Inequality: In preemptive algorithms (RR, SRTF, Priority-P), Response Time is always less than or equal to Waiting Time: $RT \le WT$.
  • Conservation of Time: Total schedule duration strictly equals the sum of all burst times plus idle times: $\text{Total Time} = \sum BT_i + \text{Idle Time}$.

Operating Systems in Practice

Real-World Operating System Connections

How commercial operating systems adapt these classical scheduling principles.

🐧 Linux Kernel (CFS)

Completely Fair Scheduler:

  • Replaces traditional queues with a Red-Black Tree indexed by virtual runtime ($vruntime$).
  • Models an ideal multi-tasking CPU where each process receives $1/n$ of processor power.
  • Interactive processes maintain lower $vruntime$, getting dispatched earlier.
🪟 Windows NT Kernel

Multi-Level Priority Queues:

  • 32 priority levels (0–15 dynamic, 16–31 real-time).
  • Uses priority boosting for foreground interactive windows and after I/O completions.
  • Employs Round Robin within each discrete priority band.
⏱️ Real-Time OS (RTOS)

Rate-Monotonic & EDF:

  • Used in avionics, robotics, and medical devices where deadlines are hard.
  • Rate-Monotonic: Shorter task period = higher priority.
  • Earliest Deadline First (EDF): Dynamic priority based on closest completion deadline.
Viva Voce Preparation

Key Viva Questions & Examiner Defenses

Prepared responses for core conceptual and technical examiner inquiries.

❓ Frequently Asked Viva Questions
  • Why is SJF optimal for average waiting time?
    Scheduling short bursts first reduces their waiting times drastically while delaying longer jobs by negligible amounts, mathematically minimizing $\frac{1}{n}\sum WT_i$.
  • What is the Convoy Effect?
    In FCFS, when a long CPU-bound process runs, all subsequent shorter I/O-bound tasks stall in the ready queue, dragging down CPU and device utilization.
🛡️ Technical Examiner Inquiries
  • How does Round Robin handle simultaneous arrivals?
    When a process quantum expires at time $t$ and a new task arrives at time $t$, newly arrived tasks are enqueued before the preempted task is re-enqueued.
  • Can Response Time ever exceed Waiting Time?
    Never ($RT \le WT$). In non-preemptive algorithms, $RT = WT$. In preemptive algorithms, $RT < WT$ if a process is preempted after starting.
Looking Forward

Limitations & Future Enhancements

Pathways to expand the platform into an enterprise-grade OS simulation lab.

⚠️ Current Simulator Scope & Limits
  • Single-Core Model: Assumes a uniprocessor system; multi-core processor affinity and load balancing are not yet modeled.
  • Static Burst Assumptions: Process CPU bursts are deterministic integers known upfront, rather than stochastic distributions.
  • Negligible Context Switch Cost: Context switch latency is treated as negligible ($0 \mu s$) for clean educational clarity.
🚀 Planned Future Enhancements
  • Multi-Level Feedback Queue (MLFQ): Dynamic queue migration with aging and priority decay based on CPU usage.
  • Symmetric Multiprocessing (SMP): Multi-core timeline visualization modeling dual-core and quad-core CPU scheduling.
  • Real-Time Scheduling: Implementation of Rate-Monotonic Scheduling (RMS) and Earliest-Deadline-First (EDF).
  • PDF Lab Report Generator: One-click generation of formatted academic laboratory reports with embedded Gantt charts.
